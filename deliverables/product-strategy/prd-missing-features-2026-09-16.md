## 📌 TL;DR（执行摘要）

- **核心目标**：让目标读者（行长 / 零售银行部 / 财富与私行 / 零售信贷负责人）在手机端 **3–8 分钟内**稳定拿到「地区动态 + 可落地商机」，而不是被动浏览一份每日快照。
- **关键决策**：当前产品**内容侧强、产品化侧弱**——内容颗粒度（广州 × 客群 × 官方源 × 语音）是别处买不到的优势，但检索、订阅、持续跟踪、线索可执行、留痕这五类**已被同类产品标准化**的能力几乎全部缺失（对标矩阵 10 个维度中 9 个为 ❌/⚠️）。

- **下一步**：按「先体验、后资产」分三期推进，第一期只做 5 条（A1/A2/F2/A5/F3），先拿即时收益并沉淀 `条目 ID + 详情页` 契约作为后续地基；**前置决策点 = 是否批准延长历史正文保留期**。

## 1. 产品定位与目标读者

**产品**：面向「某股分行」零售条线的每日资信简报站（个人整理项目，非机构立场）。每日自动跑：多源采集 → 归一化 → 关键词漏斗 → AI 两阶段富集（相关性判定 / 摘要 / 客群打标）→ 组装 → 渲染单页 HTML / Markdown / 口播稿 → 发布；另有人工触发的微信公众号 + 企业微信机器人合并推送。

**目标读者 5 类**：行长（决策视角）· 零售银行部负责人 · 财富管理与私人银行负责人 · 零售信贷负责人 · 业务管理/客群经营支撑岗。

**核心场景**：手机端（微信推送点开为主），每日 3–8 分钟，用途是「掌握地区动态 + 发现商机 + 会上有话可说」。

**本次范围**：只诊断与排序「资讯聚合」与「商机洞察」两条价值链上的缺失功能，不引入无关方向。

## 3. 用户研究洞察（来自瑞思）

### 3.1 两条典型旅程的断点

**行长（决策路径）**：微信点开 → 看定调与数据戳（只给总条数，不给本地/商机/风险占比）→ 横滑看必读 3 条（**横滑与微信内置浏览器冲突、易误触、文字截断**）→ 点开原文（**跳外链、上下文丢失、微信内无多标签无返回锚点**）→ 通勤听 4 分钟语音（**与文本非逐条对应、无时间戳，听到重点跳不回卡片**）→ 想回溯上周（**归档仅日期列表、正文只留 7 天**）→ 备会找话术（**无导出、无复制**，只能截图）→ 离开（**无反馈入口**）。

**财富/私行负责人（商机路径）**：点开 → 数据戳只给商机总数、不按客群拆 → 商机洞察 5 条（**客群标签只展示不可点，无法联动筛正文**）→ 进业务线与监管板块（**筛选栏没有客群维度**，而客群正是其核心切分轴）→ 想深挖客群轨迹（**条目间无关联视图、无收藏**）→ 区分可落地商机与泛动态（**除 IPO 外无成熟度分级**）→ 转给支行/客户经理（**无导出无订阅**）→ 评估与我方匹配度（**普通商机没有红筹页那样的「会前版本」穿透报告**）。

### 3.2 未满足需求（按痛点强度，原文 12 条）

高：N1 手机端摘要区交互重构 · N2 站内上下文阅读 · N3 归档主题化可检索 · N4 按角色的受众适配 · N5 客群升为一等切分轴 · N6 导出/复制/收藏/订阅闭环
中高：N7 商机成熟度分级与时间线 · N8「会前版本」穿透视角复用
中：N9 语音与文本逐条对应 · N10 今日 vs 昨日增量视图 · N11 读者反馈/纠错入口 · N12 数据戳颗粒度与覆盖度透明

### 3.3 关键判断

1. 优先重做手机端阅读架构（纵向优先级流 + 站内上下文）——微信内置浏览器是唯一入口，横滑冲突与外链丢失直接吃掉最核心的摘要价值。
2. 建立主题化可检索归档 + 增量视图——行长的核心收益是「追踪政策与商机后续」，7 天留存 + 日期列表让长期价值归零；红筹页的变更日志已证明该能力在本产品内可行。
3. 客群/业务线升级为一等切分轴 + 角色化视图 + 商机成熟度分级——让 AI 打标成果转化为「谁跟进」。

### 4.3 结构性缺失（11 条）

检索 · 日期切换与多期对比 · 持续性主题跟踪 · 订阅与提醒开关 · 洞察「行动项」 · 线索可执行性 · 跟进状态管理 · 读者反馈闭环 · 内容评审与留痕 · 数据导出与分享协作 · 提醒分级与时间窗。

### 4.4 差异化机会（3 条）

1. **地区颗粒度到「广东/广州」× 客群标签的交叉切分**——竞品多做到省市级或全行业，鲜有「广东 IPO 分阶段 × 广州本地 × 客群财富/信贷」的交叉；放大方式：做成可下钻的「地理 × 客群」二维筛选。
2. **官方源权威性 + 来源可追溯**——契合机构读者「引用得出手」的要求；放大方式：每条线索附来源与官方原文入口，让简报成为行内「可引用简报」。
3. **每日固定节奏 + 语音简报**——少竞品具备；放大方式：做成「通勤 3 分钟决策版」，首句给出「今日必读 + 最需关注风险」。

## 6. 产品目标（3 个正交目标）

1. **主路径效率**：让读者在手机端 3–8 分钟内、不横滑不跳转即可锁定当日真 Top 事件并完成决策阅读。
2. **资讯资产化**：把「每日快照」升级为可检索、可回溯、可追踪的资产——任一历史条目 2 次操作内定位并回原文。
3. **商机可行动**：每条商机带客群归属、成熟度与下一步动作，直接进入团队分工与备会。

## 9. 时间线 & 里程碑（来自路径）

### 9.1 分期建议：先体验、后资产

| 方案 | 判断 |
|---|---|
| 先资产（B1 先行） | ❌ B1 的检索/多期对比以历史正文为输入，而工作区只留最近 7 天——必须先「延长保留期 + 回填」，等于在 XL 项前再叠一道前置工程；且检索命中需要条目级落点，没有 A2 的详情页则「命中后无处可跳」。投入最大、见效最慢、被依赖锁死 |
| **先体验（A1/A2 先行）** | ✅ 命中每日主路径，对每位读者每天生效，价值即时；A2 实现中沉淀的「条目 ID + 详情页」契约正是 B1/B2/C1/E1/E2/A4 共同复用的地基；A1 的阈值校准为 F2/F3 的噪声治理定标。以更低依赖风险先拿即时收益，再用同一套条目/主题契约承接 XL 的 B1 |

### 9.2 分期总览

| 期 | 主题名 | 条目 | 主要工作量 |
|---|---|---|---|
| 第一期 | **主路径救火**（体验重构 + 噪声治理） | A1、A2、F2、A5、F3 | XL + L + 3S |

### 9.3 里程碑（可验证完成信号）

**第一期**
- **M1.1 首屏重构上线**：手机端微信内置浏览器打开首页，首屏无横滑卡片、仅 Top3 且标题/摘要不截断；用当日结构化 JSON 统计 2 级条目占比 ≤30%。
- **M1.2 站内阅读可达**：任一条目点开进入站内详情页（结构摘要 + 关键信息 + 来源），外链为次级入口；返回后恢复原滚动位置。

**第二期**
- **M2.1 检索与归档可用**（前置：保留期已延长并回填）：归档输入关键词可命中 3 周前条目；按客群/板块/日期多维筛选有结果；多期对比可同时加载两日快照。
- **M2.2 追踪与增量一致**：同一主题跨日时间线可连播并标注续报期次；今日 vs 昨日「新增/续报/变更」三态抽样与事件记忆库判重结果一致。

**第三期**
- **M3.1 推送可控**：1 级预警走独立高优通道；按客群/板块订阅生效；隔夜版/早间版按各自时间窗出刊（含周末出刊规则）。
- **M3.2 协作闭环**：反馈带条目 ID 可统计；单条复制/批量导出含来源与链接；收藏夹跨期可取回。

### 9.4 依赖关系

- **B1 依赖「历史正文保留期延长 + 回填」**——否则归档/检索/多期对比无足够输入。
- **B1 依赖 A2**（条目 ID / 详情页）——检索与归档命中后需可跳转的落点。
- **B2 依赖 B1**（主题聚合）——时间线按主题串连载，需先有主题归并结果。
- **B2 依赖 F1**（去重标定）——放宽同主题上限后若不合并展示/标注续报期次，时间线会出现重复节点或断点。
- **A3 依赖事件记忆库跨天判重结果**——「新增/续报第 N 期/变更」三态直接取自现有判重输出；**A3 亦依赖 A2**（变更条目需可点开详情核对）。
- **C1 依赖 A2**——客群标签点开联动正文需详情页/锚点。
- **D3 依赖现有构建/发布节奏改造**——拆隔夜版/早间版 = 每日两次构建、两个发布/推送窗口。
- **D2 依赖 D1**——提醒分级建立在订阅通道/范围之上。
- **E1、E2 依赖条目 ID**（源自 A2）；**E3 依赖 E1**。
- **A4 依赖口播稿文本 + 条目 ID**（源自 A2）——逐条时间戳需切分口播稿并对齐条目。
- **F2 / F3 / A5 无阻塞**——可直接落在既有结构化报告 JSON 上。

## ⚠️ 待确认 / 假设 / Non-goals

### 待确认问题（需产品负责人拍板）

1. **推送时间窗定在几点？** 数析显示 8:00 阅读时内容已陈旧 12–13 小时——是否拆分为「隔夜版 / 早间版」两段出刊？
2. **是否开放按角色/客群订阅？** 五类读者的定制视图是纯前端切换，还是各自独立推送？
3. **导出是否包含原文链接与来源署名？**（涉及个人整理项目的引用与版权边界）
4. **主题化归档保留期**：线上当前仅 2 期、工作区 7 天，是否上云延长至 N 个月？
5. **去重上限放宽到多少？** 由谁判定合并？如何避免单主题刷屏？
6. **跟进状态是否记录人名/团队？** 涉及可定位具体主体的合规红线如何界定？

### 假设

- 读者入口仍以微信推送 + 手机浏览器为主，不引入账号体系（v1 无登录）。
- 站点继续保持静态构建 + 每日一次节奏，不引入常驻后端服务（D3 的「两次构建」为节奏内改造）。
- 现有 AI 富集产物（摘要 / 客群标签 / `ipoStage`）可复用，不新增外部数据采购。

### Non-goals（本期不做）

1. 不做社交互动 / 点赞评论体系。
