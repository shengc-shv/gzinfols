| **工程接入** | 遵循既有技术栈 / 目录结构 / CI 配置；补必要配置、测试用例、使用文档；可重复、可维护 |

## 三、识别口径（待确认，本文给出建议口径）

### 3.1 红筹的核心判定（已确认 —— 阈值策略，保持简单可解释）

```
本项目口径：红筹 = 境外注册 ∧ 广东运营实体词频 ≥ 3
```

| 维度 | 判定依据（来自申请版本 PDF 文本） | 说明 |
|---|---|---|
| **① 境外注册**（必要条件） | 封面页固定句式，如 `Incorporated in the Cayman Islands with limited liability` → 注册地 ∈ 离岸法域集合（开曼群岛 / 百慕大 / 英属维尔京群岛…） | 仅采信**封面页/扉页**固定句式 |
| **② 广东连接**（必要条件） | 招股书「概要 / 公司资料」中**广东城市词频 ≥ 3**（`gd_opco_count ≥ 3` 同款阈值策略） | 服务本行商机；阈值单一、可解释、易调 |
| **③ VIE 架构**（仅展示，不判定） | 文本命中 `VIE` / `可变利益实体` / `协议控制`；区分「现行 / 已终止 / 未核验」 | **不参与判定**，仅作画像字段 |

> 明确**不引入**多维加权（如"中资背景强度"打分）：口径越复杂越难维护，
> 故采用与 `gd_opco_count ≥ 3` 同款的**单阈值策略**。
> 证据不足 / 未核验一律标 `unverified`，**不臆造结论**（宁缺毋滥）。

### 3.2 输出字段（每个项目）

申请编号、企业名（中/英）、板块（主板/GEM）、状态、股票代码、递表日、
注册地、是否离岸、中资背景强度（城市词频/实体数）、VIE 状态、广东连接（有/无/未核验）、
判定结果（红筹/非红筹/待核验）、发现时间（首次入快照的北京时间）、来源链接（申请版本 PDF）。

## 四、更新频率与增量策略

- **频率（2026-09-15 用户澄清）**：**随每次 CI 运行执行**——即接入现有日管线 / `daily.yml`，
  每次 CI 跑（含 cron 与手动 dispatch）都跑一次红筹监测；**不另起独立定时 workflow**。
- **抓取日期（2026-09-15 用户澄清）**：**按当次 CI 运行的日期抓取**（北京时间 / `REPORT_TZ` 当日），
  **不是抓昨天**；日期路径由运行当日决定，可用 `--date YYYY-MM-DD` 覆盖以便补跑/重跑。
- **增量**：每次先拉列表 JSON → 与最新快照比对 → **只对新增/变更的申请编号**下载并解析 PDF。
  存量项目不重复下载（省钱省时，PDF 解析是主要成本）。
- **幂等**：同一申请编号重复跑不会产生重复记录；PDF 解析结果随快照固化。

## 五、变更记录（快照 + diff + 可追溯日志）

- 快照：`data/redchip/snapshots/<YYYY-MM-DD>.json`（当日全量项目 + 判定结果）。
- 最新指针：`data/redchip/latest.json`（便于展示层直接读）。
- 变更日志：`data/redchip/changelog.jsonl`（append-only，每行一条变更）：
  `时间 / 类型(新增|移除|字段变更) / 申请编号 / 企业名 / 变更前后值 / 来源链接`。
- diff 维度：新增、移除、字段变更（注册地 / 状态 / VIE / 广东连接 / 判定结果 变化）。
- **可追溯**：每条记录带发现时间与来源链接，可回原文核对。
