## 2. 硬性红线（用户明令，不可违反）

1. **时区只认北京时间**：全项目统一 `Asia/Shanghai`，单一真源 = `lib/utils/time.ts` 的 `REPORT_TZ`。
   不接受 env 覆盖、不回落系统时区；禁止无 `timeZone` 的 `Intl.DateTimeFormat`、直接 `new Date()` 取日历日。
   CI runner 默认 UTC，回落会错日。
2. **加密资产零容忍**：任何项目不得出现加密板块/指标/文案（不移植、不渲染、不进契约）。
   注意「Token贷/词元贷」是银行信贷产品，不要误删。
3. **不得出现可定位到具体银行主体的信息**：行名全称/简称/英文缩写/内部项目代号一律禁止
   （代码注释、文档、产出物、README、package.json、记忆文件都算）。历史遗留业务词表先问用户再动。
4. **无状态源架构红线**：不得用 sourceId/category/subcategory 决定最终渲染归属
   （广州本地、板块、业务线标签），必须经漏斗 + 内容判定（如 `scoreBranchRelevance`）。
5. **时间真实性红线**：绝不用抓取时间兜底 publishedAt；无明确发布时间的条目一律废弃。
6. **业务相关性红线**：可展示内容必须能挂钩客群/财富/私行/信贷，或是国家/省/市级商机政策。宁缺毋滥。
7. **不要动辄跑全量测试**（用户对此明确不满过）：默认只跑受影响测试文件
   `node --import tsx --test tests/xxx.test.ts`；全量只在收尾或用户要求时跑，**放后台**（约 9 分钟）。
8. **已发布 vs 测试构建严格区分**：只有当天 9 点前确认交付的版本算「已发布」；无法判断标「待确认」。
9. **远程 workflow 触发须先征得用户同意**（手动 dispatch 等都会触发 GitHub Actions）。
10. **本地 AI 分析一律由助手自己逐条撰写**，不要检测/调用其他 LLM 后端。

- **验证「纯搬移」用产物指纹**：固定夹具渲染产物（默认 / 注入 baseUrl+webMode+now / Markdown）取 sha256 前后比对。
  ⚠️ **不可用 `git stash` 隔离**——会把其它未提交改动一并回退污染结论；正确做法：
  「备份当前文件 → 换回上一步版本 → 取指纹 → 还原」。探针要从 **barrel 导入**（前后两态都可用）。
- **查重复必须逐声明比对，并确认「生产 import 的是哪一份」**——已发生 3 例「测试测的不是生产代码」

- **不可信计划表/文档里的行号与进度**，以 grep 仓库真实源码为准。
- **CSS 注释会进公开页面**：`render/full.ts` 有 `stripCssComments` 在注入点剥离 THEME_CSS/AUDIO_HIGHLIGHT_CSS；
  新增 CSS 源码注释是安全的（会被剥离），但别把敏感词写进会原样输出的位置。

## 5. 日常操作要点

- **推送**：先 `git fetch origin main && git rebase origin/main`（CI 每天往 main 推归档 commit），再 `git push origin main`
  （keychain 凭据直接可用）。三个 workflow 均无 `push` 触发，推送不会启动 CI。
- **本地复现 CI 裁剪**：`npm run cleanup:history`（与 CI 同口径）。
- **站点构建**：`node scripts/build-site.mjs`（发布根 `site/` 的唯一写者；契约有测试锁定 `tests/build-site.test.ts`）。
- **改发布机制前**：📌 Pages 源 = gh-pages 分支（legacy 分支式），改机制必须同步改仓库设置，否则 deploy 必失败。
- **触发真实落盘的测试**：用 `setPersistenceBaseDir(tmp)` 隔离并清理；仓库内禁止留测试假数据。
