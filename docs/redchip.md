# 红筹项目监测与展示

数据源为港交所「披露易」**新上市申請版本及相關資料（AP & PHIP）**公开静态地址（免鉴权）。

> ⚠️ **线索 ≠ 结论（贯穿全链路的红线）**：本模块产出的是**公开信息初筛线索**，不是尽调结论。
> 所有面向读者的文案一律用「线索」口径（`REDCHIP_LABELS`），证据不全降级为「待核」；
> 每条附港交所原文链接，广东连接须回原文复核后方可用于任何业务判断。

## 识别口径

```
红筹 = 境外注册 ∧ 广东运营实体词频 ≥ 3
```

- **境外注册**：申请版本封面页固定句式（如 `Incorporated in the Cayman Islands with limited liability`）→ 注册地属离岸法域（开曼 / 百慕大 / BVI …）。
- **广东连接**：招股书文本中广东城市词频 ≥ 3（`GD_CITY_HIT_THRESHOLD`）。
- **VIE**：仅作画像展示，**不参与判定**。
- 证据不足一律 `unverified`，**不臆造结论**。

## 运行

```bash
npx tsx scripts/redchip-monitor.ts --live            # 实网抓取（默认窗口 = 今天 + 昨天）
npx tsx scripts/redchip-monitor.ts --live --date 2026-09-14 --limit 20
npx tsx scripts/redchip-monitor.ts                    # 样本模式（零网络，用于自测）
npx tsx scripts/redchip-monitor.ts --dry-run          # 只打印不写盘
```

参数：`--live` 实网 / `--sample <path>` 样本 / `--date YYYY-MM-DD` 目标日
/`--limit N` 每轮最多抽取 PDF 条数（控成本）/ `--dry-run`。

> ⏰ **日期口径（2026-09-15 修正）**：
> - 默认窗口 = **今天 + 昨天**（北京日历日 `REPORT_TZ`），两天合并后**按申请编号去重**；
> - 显式 `--date X`（补跑）**只取 X 单日**，精确复现历史某天；
> - 两天都无数据 → 回退「最近有数据日」（披露易发布有 1~2 天滞后，否则未递表日恒空）。
> - 不可用 `Date.toISOString()` 取日期（那是 UTC 日期，会错成"今天"）。
>
> **日志里「清单总量 N 条」是源清单本身的总条数，不是抓取量** —— 实际只对窗口命中的
> 记录下载申请版本 PDF，且受 `--limit` 约束。

## 窗口口径

| 环节 | 窗口 | 常量 | 语义 |
|---|---|---|---|
| 源层抓取 | 今天 + 昨天 | —（脚本内置） | 北京日历日；两天合并去重 |
| **音频口播** | **2 天** | `REDCHIP_VOICE_WINDOW_DAYS` | **日差 ≤ 2** |
| 卡片 / 会前报告展示 | 7 天 | `REDCHIP_LIST_WINDOW_DAYS` | **日差 ≤ 7** |

> ⚠️ 红筹窗口语义是「**日差 ≤ N**」（今天-N ~ 今天，共 N+1 个日历日，走 `dayGap`），
> **与 IPO 的「含今天共 N 个日历日」不同**（见 `lib/ipo-config.ts` 文件头）。两者勿混用。

## 产出

| 文件 | 入库 | 说明 |
|---|---|---|
| `data/redchip/leads.json` | ✅ **必须入库** | 线索库（渲染期读取；人工冻结快照，与 `data/local-ipo.json` 同模式） |
| `data/redchip/latest.json` | ❌ 运行时 | 最新快照 |
| `data/redchip/snapshots/<date>.json` | ❌ 运行时 | 按次归档快照 |
| `data/redchip/changelog.jsonl` | ❌ 运行时 | append-only 变更日志（新增 / 移除 / 字段变更，带来源链接） |
| `site/redchip/index.html` | ❌ | 线索总览页（`build-site.mjs` 生成，遵守 site/ 唯一写者） |
| `site/redchip/r/<leadId>.html` | ❌ | 每条线索一份**会前版本**穿透报告（见下） |

> `.gitignore` 精确忽略后三条运行时产物；**`leads.json` 不忽略**（漏提交会导致徽章与报告页全空）。

### 会前报告页（`site/redchip/r/<leadId>.html`）

- **生成条件**：`verdict ≠ non-redchip` 才产页（与徽章口径一致）；`leadId` 需匹配
  `[A-Za-z0-9_-]{1,64}`（防目录穿越）。
- **零 LLM**：纯字符串拼接，覆盖率 100% —— 修掉早期「点开是空的」问题。
- **带「会前版本 · 待深度核验」水印**；若存在深度版（`deep/`）或人工版（`manual/`），
  卡片入口**优先指向深度版**（`report-resolver` 探测，优先级 manual > deep > r）。

## 展示与播报

**清单页**含：企业名、板块、状态、递表日、注册地（离岸标记）、广东词频（粤标记）、VIE、判定、
发现时间、原文链接；支持按判定 / 板块 / 离岸 / 粤连接 / 名称筛选，按发现时间 / 递表日 / 企业名排序，
附变更历史区块（时间 / 类型 / 编号 / 字段前后值 / 来源）。

**日报内的徽章**（挂在 IPO 板块卡片上，由 `side-redchip` 实体匹配后写入 `item.redchip`）：

| 徽章 | 触发 | 语义 |
|---|---|---|
| `红筹线索` | `verdict = redchip` | 判定成立 |
| `红筹线索·待核` | 证据不全（如未拿到封面页） | 降级展示，**不臆造结论** |
| 角标「新」 | 本次 `added` | 本期新增 |
| 变更小字（如 `↑状态/注册地`） | 本次 `changed` | 取变更字段标签 |

**实体匹配顺序**（`matchRedchipLead`）：港交所申请编号 → 股票代码 → 归一化企业名。
匹配失败 → **不打标**（无状态源红线），但线索仍出现在红筹面板（`matched=false`），不静默消失。

**播报（`REDCHIP_VOICE_BOOST`，默认 2）**：

- 红筹条目**只前移、不占额外名额**（不抬高名额上限）；默认 2 表示红筹「在审」可越过非红筹「注册生效」。
- 红筹句**排在 IPO 口播段最前**；口播与事件记忆写回同源。
- ⚠️ **刻意不播「广东运营 N 处」**：`gdCityHits` 是**提及次数**而非实体个数，口播说「N 处」会失真；
  计数只在卡片 / 报告页呈现（那里配原文可核对）。

## CI

`.github/workflows/daily.yml` 中的「红筹监测」步骤随**每次 CI 运行**执行（`continue-on-error`，
不阻断日报主线）；随后 `build-site` 用其快照产出展示页与每线索报告页。

> 注意：`leads.json` 由 CI 的红筹监测步骤产出。**首次配置后需跑完一次 daily 才会在仓库里出现**，
> 此前徽章 / 面板 / 报告页均为空态（属预期，不是故障）。

## 复核

页面与日志记录均为**公开信息初筛**，线索 ≠ 结论；每条附港交所原文链接，广东连接须回原文复核。
